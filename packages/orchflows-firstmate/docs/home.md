# Home

```text
~/.orchflows-firstmate/
├── README.md  .gitignore            seeded once                       yours
├── libraries/<library>/             your saved workflow libraries     yours
├── .agents/plugins/marketplace.json Codex catalog of the libraries    regenerated by setup
├── .claude-plugin/marketplace.json  Claude catalog of the libraries   regenerated by setup
└── artifacts/                       optional scratch                  ignored
```

The home holds only what you author. The core is the checkout installed as a plugin per [hosts.md](hosts.md#register-and-refresh); FirstMate owns every agent, worktree, steer, merge and record. The home is also a registered `local-only` FirstMate project, so [orch-build-workflow](../skills/orch-build-workflow/SKILL.md) ships a library into it as an ordinary FirstMate task and FirstMate lands the branch.

Home selection: `--home PATH` → `ORCHFLOWS_FIRSTMATE_HOME` → `~/.orchflows-firstmate`; never the current directory. `ORCHFLOWS_HOME` does not select this package's home, and setup refuses a home that overlaps a normal Orchflows home or catalog. Package contracts: [architecture.md](architecture.md).

CLI: `python <core>/scripts/orchflows.py COMMAND`, using any Python 3.11+; no dependencies. Commands return one JSON line on stdout. Exit 0: success; 1: `issues` present; 2: command error (JSON on stderr) or argument error. Use `COMMAND --help` for flags.

## setup

`setup [--home PATH]`

- Creates `libraries/` and both `orchflows-firstmate-home` catalogs, listing every valid library by a path relative to the home; seeds `README.md` and `.gitignore` once; runs `git init` if available, never commits. Rerun after adding or changing a library to regenerate the catalogs. Existing seeded files and library contents are never rewritten.
- Changes nothing outside the home: no host setting, no FirstMate file, no copy of the core.
- Result: `status`, `home`, `files`, `libraries` (`name`, `version`, `package_root`), `git`, `issues`.

## doctor

`doctor [--home PATH]`

Read-only checks: library manifests and `skills/`, seeded files, catalogs against the libraries. Returns `checks`, `issues` and `status: ready|incomplete`. It does not inspect FirstMate or the host.

## Libraries

Edit `libraries/<name>/`. Names must be unique across the home and cannot be `orchflows` or `orchflows-firstmate`; a linked directory is reported and left out. A saved workflow lives at `<home>/libraries/<library>/skills/<workflow>/SKILL.md`, which is where the captain reads it when the request names it. After adding a library, rerun setup, then [register or refresh](hosts.md#register-and-refresh) it with the primary's harness only if you also want it by slash command. Bump manifest versions before refreshing a changed library; Claude Code can retain stale cached files at the same version.

## Authoring

Register the home as a `local-only` FirstMate project with [no origin remote](firstmate.md#local-only-projects). [orch-build-workflow](../skills/orch-build-workflow/SKILL.md) dispatches a Work agent that ships a library into `libraries/<name>/`; after FirstMate merges it, rerun setup to list it. FirstMate itself never writes into the home.

## Another computer

Clone the home, install the core checkout there, run `setup --home <clone>`, then [register or refresh](hosts.md#register-and-refresh) what you want by slash command. Setup downloads nothing; `artifacts/` and Python caches are ignored by the seeded `.gitignore`.
