# Single independent Review primitive

The Review increment extends the existing one-component contract with a
standalone read-only audit. It is a step toward Orchflows parity; it does not
yet compose multiple Work tasks and a final Review.

## Admission and identity

FirstMate admits an immutable Linux attachment before launching the normal
root scout. Work with review policy none remains the default. Review requires
both primitive Review and review_policy explicit-audit; the policy is an
explicit requested deliverable, not an extra delivery gate inferred from
plugin installation.

The same clean no-origin Git commit, complete retained package, epoch,
one-component reservation and inherited Claude/Codex controls apply. Review
keeps protocol version 1 and uses the distinct local-readonly-review view
scope. The default protocol response remains compatible with Work and
advertises Review separately. Existing Work records remain readable.

The root client explicitly requests its admitted primitive. Requests still
contain only request_id and assignment. Primitive/policy identity comes from
the immutable attachment and is checked against durable request, metadata and
result records. Reattachment cannot change it, and stale generations cannot
submit, complete or gather.

## Reviewer and delivery

A fresh FirstMate-owned component reviews the frozen input commit using Review
guidance. It cannot repair the candidate, create other workers, invoke normal
scout completion or deliver the root's result. It returns its bounded UTF-8
audit report through the existing component completion owner. FirstMate
validates the worktree, retains the result and notifies the current parent.

The root reads the complete retained report and result before gathering. The
root alone prepares and delivers the ordinary scout audit report. Repeated
gather preserves the first acknowledgement timestamp while recording the
current acknowledging parent generation; retries cannot rewrite when the
result was first acknowledged. Existing
launch custody, immutable replay, parent recovery, watcher projection and
cleanup guards remain authoritative. An uncertain launch remains unresolved
and never authorizes a replacement reviewer.

A completed Work attachment cannot accept Review as a second request. Review
of joined dirty writer state, parallel makers, arbitrary report/artifact
snapshots and workflow-owned repair passes need a later composition contract.
The initial audit profile does not imply those capabilities.

## Validation

Fixture results, actual Linux worker trials and the final independent
development review are recorded separately in the increment's verification
document. A successful package doctor is still package-only readiness and
cannot authorize a worker or assert full fleet integration.
