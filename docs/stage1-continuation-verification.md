## Observed problems and changes

The real Claude trial completed Work, gathering and ordinary root delivery, but its ordinary watcher raised attention while FirstMate was still admitting the component. The request existed before child generation publication, so the prior observer could not distinguish the active launch from an abandoned one. The [runtime continuation](stage1-acceptance-continuation.md) preserves this failed watcher assertion separately from successful Work and cleanup.

The controller now records launch custody before request publication on Linux: the ordinary parent control/metadata lock claims, owner/controller process identities and ancestry. The observer checks that exact current transaction and root generation without acquiring or replacing its locks. A proved in-progress launch projects waiting; missing, changed, dead or uncertain custody stays actionable. Once launch is published, the existing child endpoint/activity path takes over. There is no timer grace, inferred endpoint liveness or automatic redispatch. Other platforms do not claim this positive Linux custody proof.

Actual native Windows Herdr and Treehouse probes passed basic endpoint/worktree operations but exposed incompatible endpoint and process owners. A detached child survived both workspace closure and lab teardown. The probe stopped that child through its retained Windows handle. See [native Windows evidence](stage1-windows-native.md), including the separate attached-child success and exact runtime identities.

The real FirstMate spawn entrypoint therefore refuses native Windows Stage 1 workers before task locks, relaunch stop or endpoint/worktree allocation, and rechecks inside the locked binding. There is no environment switch enabling these unsupported workers. Native teardown refuses before task cleanup, including `--force`. On POSIX, an attached Stage 1 task now retains its records, worktree and temporary outputs if missing `lsof` prevents the existing process cleanup owner from establishing its result. Fallback failures propagate through the actual cleanup transaction. This is a bounded admission/retention repair; full native Windows custody remains required implementation work.

A separate real observation found Claude's long shell command still running after the model turn ended, while FirstMate classified its component unknown. The later acceptance fixture keeps the shell in the foreground using documented private harness settings. That fixture does not establish native background-tool supervision. The broader activity/termination contract remains open before writers or full parity.
