## Against the skills and docs

- **Invocation policy.** The dynamic workflow was loaded through the Skill tool by description. `orch-work`, `orch-review` and `orch-build-workflow` were never loaded that way: the first two were read by path through the workflow's links, and build-workflow by path from the core when named. The saved workflow was read from the library path when named. This is the behavior `docs/architecture.md#invocation` and the `captain.md` block describe.
- **Wait for the reviewer.** Every repair decision followed a read of the report at the review's `done:` wake; the clean verdicts skipped repair explicitly.
- **Build-workflow's trial contract.** The trial ran the draft as written from the unmerged branch, the record listed preparation, intervention and unexercised paths, findings went to the author before the final review, and the final reviewer received the candidate and the trial record. No behavioral improvement claim was made, and both the primary and the reviewer said the refined draft was not re-run.
- **Model and effort.** Every spawn carried explicit `--harness --model --effort` flags: the dispatch rules for the dynamic runs, the saved preferences for the workflow runs.
- **Guidance selection.** `code` and `writing` for the CLI build, `orchflows` and `writing` for authoring, `code` for the saved workflow once its refinement named it. The primary flagged the draft's missing guidance itself.
- **Backlog notes, holds, landing, teardown.** The `orchflows: <workflow> phase=… work=… review=… repair=… guidance=…` note was kept on every request item; every landing went through a captain hold, `fm-merge-local.sh` and `fm-teardown.sh`; the library landing was followed by `doctor`.

What it did that the docs do not cover:

- It spawned once with the project name instead of its path and recovered from FirstMate's error in four seconds. `docs/firstmate.md` now says spawn takes the clone path.
- It added the captain's registration ruling to `captain.md` as a standing preference. That is FirstMate's captain-preferences behavior, outside this library.
- It checked the host's plugin list to learn how the package was loaded before proposing registration options for the new library.

## Environment lessons

- Ubuntu's `/tmp` is cleared whenever the WSL VM restarts, and the VM stops seconds after its last process exits. The September 15 lab under `/tmp/orchflows-e2e` was gone; this lab lives under `~/orchflows-e2e` and the drivers are repointed there.
- `fm-herdr-lab.sh provision` refuses without a running default Herdr session (its fleet-state tripwire). A headless `herdr server` started detached satisfies it; it was stopped after teardown.
- Driver scripts checked out on Windows carried CRLF endings that bash in WSL rejects. `.gitattributes` now pins `*.sh`, `*.py` and `*.txt` to LF.
- A primary launched with `--plugin-dir` and `--setting-sources project,local` still sees the operator's global `CLAUDE.md` import and asks about it; declining the external import leaves the primary with the plugin's skills and FirstMate's own project files only.
