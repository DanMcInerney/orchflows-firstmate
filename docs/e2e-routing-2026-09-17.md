# Live E2E: FirstMate-owned dispatch, September 17, 2026

Four live scenarios on package 0.5.0 produced correct artifacts and followed
their workflow composition. The strict suite **failed** because the primary
omitted FirstMate's native dispatch resolver for 11 of 12 worker briefs. That
finding is retained as a failing assertion; FirstMate was not patched.

The reusable [test harness](../tests/e2e/README.md) lives outside the installable
package. It prepares disposable projects, sends top-level captain requests,
records native execution, and independently tests exported commits. FirstMate
owns every worker, review, repair, worktree and merge. No generated example
library is shipped.

## What was exercised

The artifact was an exact-cent CSV aggregation CLI, `moneylog.py`, with
arbitrary integer precision, sorted account names, file/stdin input, atomic
errors and useful diagnostics. The independent oracle tested the delivered
commits, not workers' success messages. It covered amounts longer than 140,000
digits, malformed CSV, Unicode, physical line numbers, invalid UTF-8, seeded
generated ledgers, runnable README samples, and each delivered unit suite.
The final case also compared unflagged output against the original dynamic
commit and checked the new `--total` interface and documented output.

The unnamed build loaded the dynamic skill automatically. Its reviewer found
that the CSV field limit broke arbitrary precision; FirstMate returned the
finding to the maker through native steering and landed the repaired commit.

The named authoring request produced `cashflow:change`, with separate planning,
implementation and independent review. FirstMate trialed it on a fresh project,
returned observed wording gaps to the author, and obtained an independent final
library review. That review required two more wording repairs, which the
original author made before delivery. The delivered home passed the package
doctor; the library had matching manifests, manual-only invocation policies,
portable dependencies and no saved harness/model/effort pins.

The reuse case started a new primary conversation. It loaded the delivered
workflow by path, dispatched a planner before the maker and a fresh reviewer
after the maker, and preserved the library unchanged. Its reviewer found a
4,300-digit integer conversion failure and an inaccurate UTF-8 error offset.
FirstMate steered one repair pass and delivered the repaired result. The final
dynamic follow-up needed no repair. Reviewed revisions were verified as
ancestors of each exact delivered commit, including cases repaired after review.

## Observed routing

All 12 workers recorded `harness=claude`, `model=default`. Native response
records identify **claude-opus-5** for every worker and both primaries. Native
effort records agree with each worker's FirstMate metadata:

| Workers | Effort |
| --- | --- |
| Workflow author, final library reviewer | high |
| Dynamic maker/reviewer, trial planner/maker/reviewer, saved planner/maker/reviewer, final dynamic reviewer | medium |
| Final dynamic maker adding `--total` | low |

No dispatch rules were injected and typed resolution was off in this isolated
configuration. FirstMate's own [dispatch instruction at the tested revision](https://github.com/kunchenguid/firstmate/blob/3eb5b6334a80e06083e3837f0032a5cec39b8e52/AGENTS.md#L230)
requires a resolver call on every written brief, even when the result is off.
Only the first maker's call was present in the captured primary tool calls;
the remaining 11 briefs had none. With typed routing off, this did not change
the documented fallback outcome. The trace omission is still a failure of the
native instruction contract.

This run shows that workflow composition can operate without storing execution
preferences, and that FirstMate varied effort. It does not demonstrate cheaper
model selection or validate configured smart routing. No custom routing policy,
FirstMate patch or library workaround was added to make the test pass.

## Evidence, interventions and limits

The private lab is `/var/tmp/orchflows-e2e-20260917`, retained after guarded
named-lab teardown. The compact generated report and per-case JSON are under
the ignored `artifacts/e2e-2026-09-17/` directory. Roughly 82 MiB of private
evidence includes full native transcripts, tool calls, versioned briefs,
reports, statuses, steering records, backlog, observed process flags, native
model/effort/usage fields, exact artifact exports and oracle input/output.
Credentials and isolated Claude configuration are excluded. No monetary cost
is inferred from token usage.

Two inspected first-use dialogs were handled before requests began. The test
driver was restarted once while FirstMate continued running, to add the fresh
primary boundary before saved reuse. No worker was manually repaired or steered
by the driver. An earlier setup location inherited unrelated ancestor
instructions; it was abandoned before work and its named session closed.

The harness was developed during this first run: assertions were strengthened
and an abbreviated Git SHA parser was corrected. The final verifier was rerun
against each preserved delivered commit. The core package and FirstMate source
were unchanged during live work. Ten-second process sampling can miss short
processes; the native transcripts provide complementary evidence.

Coverage is one generated saved workflow, one local-only artifact family and
two Claude primary conversations. Still untested: migration of legacy saved
profile settings in a live run, configured multi-model/quota routing,
`direct-PR`/`no-mistakes` delivery and a Codex primary.
